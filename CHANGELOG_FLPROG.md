# Изменения FLProg_Ring

## 1.0.1 — 2026-11-10 (кандидат на принятие)

### Исправления

1. Состояние приёма UART-пакета сохраняется между вызовами `pool()`. Неполный пакет больше не отбрасывается в конце каждого вызова.
2. Восстановление после зависшего неполного кадра по уже имевшемуся полю `_timeout=100` мс; переполнение `millis()` учтено. Тайм-аут проверяется до чтения нового буфера.
3. Разбор идентификаторов отправителя и переменной переведён с `String::toInt()` на контролируемый десятичный `uint32_t`, включая `4294967295`, с отбраковкой ошибочных/переполненных чисел.
4. `FLProgUnsignedLonRingVariable::setValueString()` теперь принимает весь диапазон `uint32_t`; `value()` возвращает `uint32_t`, соответствующий внутреннему полю.
5. Добавлена инициализация значений переменных по умолчанию — без неопределённого значения при чтении до первой записи.
6. Добавлено освобождение внутренних массивов указателей `FLProgRing` (сами объекты переменных не удаляются); копирование экземпляра запрещено.
7. Поиск переменных больше не прерывается при встрече пустой ячейки списка.
8. Предусмотрен безопасный пустой `executor`, без разыменования `nullptr`.
9. Исправлен пример: конструктору передаётся объект UART и вызван `beginUart()`.

### Документация и API

- В заголовки и реализации добавлены русские комментарии к назначению классов, режимам, владению и обработке кадра.
- Добавлены `README_RU.md`, `AUDIT_FLPROG.md`, автономные тесты.
- Все имена публичных методов и констант остались прежними. Единственное изменение типа возвращаемого значения: `FLProgUnsignedLonRingVariable::value()` теперь `uint32_t` вместо ошибочного `int32_t`.
- `keywords.txt` проверен: 29 записей, без повторов/устаревших имён, обновлять не потребовалось.
- Версия `library.properties` изменена с `1.0.0` на `1.0.1`.

### Не изменялось

- UART-формат кадров, номера управляющих байтов, поведение `isSingleMode`, локальная отметка `isNeedSend`, формат `float` (2 знака), логика `setSkippingEvents`.
- Сторонние драйверы RT_HW и любые другие библиотеки.
