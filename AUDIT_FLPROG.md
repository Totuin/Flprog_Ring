# Аудит Flprog_Ring — 1.0.1

## Исходные материалы

Эталон: `libraries.zip` от 2026-11-10, папка `libraries/Flprog_Ring` (версия 1.0.0). Проверка с интерфейсом `FlprogAbstractUartExecutor` из принятой Flprog_Utilites 1.0.1. Изменена только библиотека `Flprog_Ring`.

## Подтверждённые проблемы исходника

- `readNextVariable()` сбрасывал `_workMode` даже если пакет заканчивался не в текущем вызове `pool()`. Фрагментация UART делала приём неработоспособным.
- Использование `String::toInt()` для `uint32_t sender/index` и входящего `unsigned long` теряло значения за пределами знакового 32-битного диапазона.
- Значения типизированных переменных не инициализировались и могли быть прочитаны до установки.
- Выделенные в конструкторе массивы указателей никогда не освобождались.
- `FLProgUnsignedLonRingVariable::value()` возвращал `int32_t` при хранимом `uint32_t`.
- Пример `FLProgRing.ino` вызывал конструктор с четырьмя параметрами при необходимых пяти и потому не мог компилироваться в таком виде.
- В циклах обработки переменных использовался преждевременный `return` при пустой записи списка.

## Ограничения и риски

1. Реальная компиляция с RT_HW и Arduino core и физический кольцевой обмен не проверялись; необходима проверка на стороне пользователя.
2. UART-протокол не экранирует служебные байты (особенно `0x04`) в содержимом `String`; строка с такими символами не передаётся корректно. Исправление потребовало бы согласованного изменения протокола всех устройств.
3. Значения float продолжают сериализоваться с точностью до двух знаков; изменение без отдельного решения нежелательно.
4. Максимальная длина строкового значения в протоколе не нормирована. Долгие/злонамеренные потоки без `0x04` могут увеличивать потребление RAM через `String` (для публичного протокола понадобится отдельное согласование лимита).
5. Для одномоментной отправки ожидается уже настроенный UART. Внутри `FlprogUartExecutor` первый вызов записи может только инициализировать устройство, поэтому в примере явно вызывается `beginUart()`.
6. Метод `nextSendVariableIndex()` исторически возвращает `int16_t`; регистрации десятков тысяч переменных не рассчитаны на ресурсно-ограниченные микроконтроллеры, но отдельное изменение API не производилось.
